---

## Git Workflow

1. GitHub Desktop에서 최신 내용을 Pull
2. main 브랜치에서 새로운 브랜치 생성
3. 작업 진행
4. Commit
5. Push
6. Pull Request 생성
7. Merge

---

## Branch Naming

형식

```
feat/기능명-이름
```

예시

```
feat/map-juyeon
feat/map-yujin
feat/ui-seong
feat/ui-chan
```

---

## Commit Message

```
feat: 새로운 기능 추가
fix: 버그 수정
docs: 문서 수정
chore: 프로젝트 설정 및 기타 작업
refactor: 코드 리팩토링
style: 코드 스타일 수정
```

예시

```
feat: add player movement
fix: resolve collision bug
docs: update README
chore: initialize project
```

---

## Team Rules

- 작업 시작 전 반드시 Pull
- 작업은 개인 브랜치에서 진행
- 작업 완료 후 Push
- Pull Request 생성 후 Merge
- main 브랜치에서 직접 작업하지 않기

---

## Unity Rules

- Unity Editor 외부에서 Assets 파일 이동 금지
- 파일 및 폴더 이동은 반드시 Unity Editor(Project 창)에서 진행
- Scene은 동시에 여러 명이 수정하지 않기
- Scene 작업 전 개발방에 작업 중임을 공유
- 큰 구조 변경 시 개발팀과 먼저 상의하기

---

## Scene Rule

동일한 Scene은 동시에 두 명 이상 수정하지 않습니다.

Scene 작업이 필요한 경우 개발방에 먼저 알려주세요.

예시

```
오늘 Stage1 Scene 작업하겠습니다.
```
